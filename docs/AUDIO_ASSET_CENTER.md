# 音频资产中心：产品模型与用户链路

> 状态：待评审，文档先行；本文件不代表已经实现。<br>
> 目标：统一「音频库」和「音色库」的资产关系，作为后续数据模型、接口与界面实现的验收基线。

## 1. 要解决的问题

当前产品把两件本来有血缘关系的事做成了两个孤岛：

- 音频库是历史生成文件的列表；
- 音色库是人工上传并注册到 `personas.json` 的少量条目。

结果是用户无法回答三个基本问题：这段音频由哪个音色生成、这段人声能否沉淀为音色、一个音色来自哪里且被哪些作品使用。文件数量也不能代表资产数量：音乐、多人对话与带噪人声不应自动成为可克隆音色。

**产品结论：** 不在两个库之间补一颗跳转按钮；要建立一个以统一资产关系为真源的「资产中心」。音频文件、音色、表达风格和作品都在同一条可追溯关系中，音色库只是其中可复用声音资产的视图。

## 2. 目标与边界

### 目标

1. 所有生成或导入的音频均可在同一处被检索、试听、追溯和复用。
2. 每个 TTS / 对话成品都能显示其使用的音色；音色能反查来源和使用记录。
3. 用户能从合格的单人语音提取音色，而不需要先下载再重新上传。
4. 把授权、音质和处理状态放在动作前面，避免不适合的素材进入音色库。
5. 删除、归档和备份都有可解释的依赖关系，不因删一条列表记录而损坏可用音色。

### 不做

- 不将所有产出自动注册为音色。
- 不允许用音乐、多人重叠对话、明显带伴奏或无授权的音频直接克隆。
- 不因生成音频所属某个音色，就反向改写该音色的参考样音。
- 不以扫描目录或文件名规则作为长期资产关系的唯一来源。

## 3. 统一资产模型

```text
资产中心（关系唯一真源）
├─ 成品与导入音频 AudioAsset（TTS / 对话 / 音乐 / 导入）
├─ 音色档案 VoiceProfile（由导入、录音或 AI 设计建立）
│   └─ 表达风格 ExpressionProfile（语气、节奏、情绪的可控预设）
└─ 后续生成记录 Generation（明确引用声音、音色与表达风格）
```

### 3.1 音频资产 `AudioAsset`

一条音频资产表示一个可播放的原始文件或由它裁剪出的片段。最低需要保存：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定 ID；界面、接口和关联均不依赖文件名 |
| `kind` | `speech`、`dialogue`、`music`、`mixed`、`unknown` |
| `origin` | `tts`、`voice_design`、`dialogue`、`music_generation`、`import` |
| `parent_audio_id` | 若为裁剪片段，指向原始音频 |
| `source_voice_id` | 若生成时使用了音色，指向该音色 |
| `rights_status` | `confirmed`、`unknown`、`restricted` |
| `eligibility` | `eligible`、`needs_review`、`not_eligible` 与原因 |
| `storage` | 受控存储位置、时长、格式、校验值、备份状态 |
| `lifecycle` | `active`、`archived`、`deleted` |

### 3.2 音色档案 `VoiceProfile`

音色不是一个文件，而是一份可复用声音档案：

| 字段 | 含义 |
| --- | --- |
| `id` / `key` / `name` | 稳定内部 ID、用户可见名称与兼容旧 CLI 的 key |
| `reference_clip_id` | 实际供模型使用的标准参考片段 |
| `origin_audio_id` | 该片段追溯到的最初音频资产 |
| `instruction` / `description` | 音色特征、使用提示 |
| `rights_status` | 来源授权及确认时间 |
| `status` | `processing`、`ready`、`unavailable`、`archived` |
| `usage_count` | 被 TTS / 对话作品引用的次数；由生成记录计算 |

`personas.json` 可以在迁移期作为兼容投影，但不再是唯一真源。

### 3.3 音色来源 `source_type` 与表达风格 `ExpressionProfile`

VoxFlow 是本地单用户 Web UI，不引入账户、租户或“声音身份归属”对象。用户看到和管理的核心对象就是 `VoiceProfile`，且**只能由三种来源创建**：

| `source_type` | 创建方式 | 必须保留的关系 |
| --- | --- | --- |
| `imported` | 导入本地文件，或从资产中心选择已有单人语音 | `origin_audio_id` 与标准参考片段 |
| `recorded` | 在浏览器直接录音 | 原始录音资产与标准参考片段 |
| `ai_designed` | 填写声音描述，由 AI 生成试音后注册 | 设计参数、生成记录与试音资产 |

所有来源最终都形成同一种 `VoiceProfile`，包含 Key、名称、描述、参考片段和来源；后续克隆、对话、歌曲工作台只选择音色，不关心它最初来自导入、录音还是 AI 设计。

`ExpressionProfile` 是音色下的可控表达预设，例如自然、沉稳、热情、轻柔。它保存语气、语速、情绪、停顿与适用场景；它不是新的音色，更不是新的身份。这就是“裂变”：**同一个音色产生受控的多种表达和作品，始终可反查到原音色。**

本地模式不对声音所有权做账户级认证或证据托管；使用导入素材时，用户仍须自行保证拥有必要的使用许可。

## 4. 本地音色的主链路

### 链路 A：三种音色创建入口

```text
导入音频 ─┐
浏览器录音 ├→ 质量检查与裁剪 → 标准参考片段 → 注册 VoiceProfile
AI 设计 ──┘                                      → 标注 source_type
```

1. **导入音频**：上传本地文件，或从资产中心选一条合格单人语音；完成裁剪/清理后注册音色。
2. **浏览器录音**：录制指定短句，原始录音先进入资产中心；检查时长、静音、噪声和音量，合格后注册音色。
3. **AI 设计**：填写声音描述和短句，生成试音；用户决定是否“注册为音色”，而不是自动把每次试音入库。

三条入口最后都进入同一个音色库。首版不承诺“录一段就可生成一切”：语音克隆、情绪控制和歌唱需要的样本质量与数量不同，界面必须分别显示能力就绪状态。

### 链路 B：用音色裂变表达与语音作品

```text
选择音色 → 选择或新建表达风格 → 输入文案 / 选择脚本
→ 生成语音作品 → 成品写入资产中心
→ 记录：音色 → 表达风格 → 生成参数 / 文案
```

- 默认提供自然、沉稳、热情、轻柔等表达风格；用户可新建预设。
- 修改表达风格只影响之后的生成，绝不改写旧作品、原始录音或 AI 设计参数。
- 每段成品均可反查它使用的音色和表达风格。

### 链路 C：用选中音色生成音乐

音乐必须拆成两个产品能力：

| 能力 | 用户得到什么 | 与音色的关系 |
| --- | --- | --- |
| 配乐 / 纯音乐生成 | 乐曲、伴奏、封面等音乐资产 | 不使用音色，不应伪称使用某个音色 |
| 音色演唱的歌曲生成 | 歌词、旋律、伴奏与人声音轨组成的歌曲 | 明确引用选中的 `VoiceProfile` 与歌唱预设 |

```text
选择可用于歌唱的音色 → 补充演唱样本（若需要）
→ 质量/能力检查 → 选择歌词、曲风、旋律/伴奏与歌唱风格
→ 生成歌曲与分轨（如能力支持）
→ 成品记录音色、歌词来源、音乐来源与发布状态
```

若当前模型只支持生成音乐或普通 TTS，产品必须明确显示“暂不支持以该音色演唱”，不能把生成的歌曲说成由选中音色演唱。只有实际支持音频条件化歌唱且完成样本要求后，才显示该能力。

### 链路 D：回看与归档

```text
音色详情 → 来源音频 / AI 设计参数 / 表达风格 / 语音作品 / 歌曲作品
→ 查看每条资产的来源 → 归档音色或其表达风格
```

- 归档音色后，禁止新生成；历史作品保留“曾使用的音色”快照。
- 删除来源录音或参考片段前，界面需说明依赖的音色与作品；引用仍存在时优先归档。
- 用户可单独归档某种表达风格，不影响同一音色下的其他预设。

## 5. 资产中心的通用链路

### 链路 E：生成后追溯（正向关联）

```text
选择音色 → 生成 TTS / 对话 → 创建音频资产
→ 音频卡显示「使用音色：老陈·人文旁白」
→ 点击可进入该音色详情
```

- TTS 单人作品保存一个 `source_voice_id`。
- 对话作品保存多个说话人及音色引用；合成音频的详情展示角色—音色清单。
- 音乐默认没有 `source_voice_id`；若未来支持人声角色，须以明确的声轨/角色关系记录，不能仅凭文件名推断。

### 链路 F：从音频沉淀音色（反向关联）

```text
资产中心选中一段语音
→ 「提取为音色」
→ 授权确认 + 人声质量检查
→ 选择或自动推荐 3–15 秒干净片段
→ 填写名称、描述和用途
→ 生成标准参考片段
→ 创建音色档案，回到音色库即可使用
```

入口只在满足以下条件时显示为主操作：单人语音或已分离出的单人声轨、授权已确认、音频未归档且基础质量合格。

| 情况 | 界面行为 |
| --- | --- |
| 合格单人语音 | `提取为音色` |
| 时长不足、静音过多、噪声较重 | `需裁剪/清理后提取`，进入片段编辑 |
| 音乐、多人重叠、混合素材 | 不提供提取；解释原因 |
| 授权未知或受限 | 先要求确认/补充授权；未确认不得创建 |

生成过的 TTS 成品也可以作为候选来源，但应显示「该成品使用的原音色」，优先引导用户复用原音色，避免无意义地从同一声音重复建档。

### 链路 G：音色复用与反查

```text
音色库选一个音色 → 查看来源片段、授权、特征和作品数
→ 查看「由此音色生成」的所有音频
→ 在克隆合成 / 对话中直接选用
```

音色详情至少有三块：参考片段与来源、生成历史、可执行操作（编辑、归档、在工作台使用）。点击任一生成作品应返回资产中心的该音频详情。

### 链路 H：删除与归档

- 删除没有被任何音色引用的音频：允许删除，记录审计事件。
- 原始音频已被提取为音色：默认归档而非物理删除；界面需说明依赖的音色数量。
- 删除音色：不得删除历史作品；历史作品保留「曾使用的音色」快照，并标为已归档。
- 参考片段不可用：音色状态变为 `unavailable`，禁止新生成，但不抹去历史关系。

## 6. 信息架构

### 6.1 登录后的创作与发布指挥台

登录后的首页不是“功能入口集合”，而是用户今天的工作判断页。它首先回答四件事：**我正在做什么、下一步该做什么、哪些作品卡住了、哪些作品可以或正在发布。**

```text
登录 → 创作与发布指挥台
├─ 当前目标：创建/复刻音色 / 参考音乐创作 / 创作歌曲 / 发布作品
├─ 继续推进：唯一最重要的下一步动作
├─ 作品进度：草稿、待补资料、待发布、发布中、已发布、异常
└─ 发布概览：待发布歌曲数、资料完整度、三个账号的状态与结果
```

“当前目标”是可随时切换的工作意图，不是一次性问卷，也不应永久隐藏其他能力。它决定首页优先级：

| 当前目标 | 首页首要信息 | 主操作 |
| --- | --- | --- |
| 创建/复刻音色 | 导入、录音、AI 设计三种入口与样本质量 | 继续录制 / 导入 / AI 设计 |
| 参考音乐创作 | 参考素材授权、歌词/曲风/伴奏进度 | 继续创作 |
| 创作歌曲 | 当前歌曲草稿、歌词、封面、音频和演唱能力 | 继续制作歌曲 |
| 发布作品 | 待发布数、缺失字段、账号登录与各平台进度 | 补齐资料 / 提交发布 |

“复刻声音”与“参考音乐创作”必须分开。后者仅面向用户拥有或获授权的参考素材，不能把复制受版权保护歌曲的能力包装为常规“复刻”。

首页不放泛泛的“累计生成次数”作为主信息。它应以作品为单位显示真正影响交付的状态：

| 作品状态 | 含义 | 首页要给出的动作 |
| --- | --- | --- |
| `draft` | 创作尚未形成可交付作品 | 继续创作 |
| `generating` | 音频、封面或歌曲仍在生成 | 查看进度 / 失败重试 |
| `metadata_incomplete` | 已有成品，但歌词、封面、版权声明等不完整 | 补齐缺失字段 |
| `ready_for_publish` | 作品与发布资料完整，等待选择账号 | 去发布 |
| `submitting` | 正在提交或等待平台反馈 | 查看账号进度 |
| `published` | 已在至少一个账号发布成功 | 查看发布记录 |
| `attention_needed` | 登录失效、审核驳回、备份失败或资料冲突 | 优先处理问题 |

一个作品 `WorkItem` 至少关联歌词、音频资产、封面、音色与表达风格（若有）、版权与 AI 声明、目标平台和各账号发布记录。**“待发布有几首”应由状态为 `ready_for_publish` 的作品实时计算；“资料是否完善”应由必填字段白名单逐项校验，而不是靠人工猜测。**

### 6.2 发布队列与账号状态

发布区域以“歌曲 × 平台账号”为单位，而非只展示三个登录卡片：

```text
待发布 3 首
├─ 《竹影孤行》：资料完整 → 汽水账号待提交 / 网易账号待选择
├─ 《……》：缺封面 → 不能发布，点击补齐
└─ 《……》：腾讯账号审核中 → 查看提交时间与平台返回

账号状态
├─ 汽水音乐账号：登录可用 / 发布 4 首 / 1 首待提交
├─ 网易云音乐人账号：需重新登录 / 2 首资料待补
└─ 腾讯音乐人账号：审核中 1 首 / 已发布 3 首
```

每个账号都要显示真实登录状态、该账号下作品的发布状态、最近错误和待办数量。歌曲详情同时显示：标题、版本、歌词、封面、音频、AI 声明、版权/授权、云备份、目标平台和每个平台的提交/审核/发布记录。任何一项未知都显示为未知或待补，不能以“已就绪”替代。

主导航使用 **资产中心**，而不是两个同级但互不理解的仓库：

```text
资产中心
├─ 全部音频（默认）：TTS、对话、音乐、导入音频
├─ 待处理候选：可提取、需裁剪、待授权
└─ 音色：可复用的 VoiceProfile
   ├─ 导入创建
   ├─ 录音创建
   └─ AI 设计创建
```

所有列表采用同一套筛选：项目、类型、来源、音色、时间、授权、备份、状态。音频卡片显示类型、来源、时长、云备份、使用音色/候选状态；音色卡片显示来源、授权、可用状态、被使用次数。空状态不造假：没有资产就指向生成/导入，没有音色就引导导入参考音频或从现有语音提取。

## 7. 关键交互与状态

### 7.1 「提取为音色」向导

1. **资格检查**：告知识别出的类型、质量、授权状态和不可继续的原因。
2. **选片段**：默认推荐干净片段；用户可试听、裁剪并确认。保留原始音频，不覆盖。
3. **建立档案**：填写名称、Key、描述、用途；Key 冲突须当场提示。
4. **处理结果**：显示处理进度和失败可恢复动作；成功后返回新增音色与其来源关系。

### 7.2 状态文案原则

- 不用“已入库”混淆文件存在和音色可用；分别写「音频已保存」「候选待处理」「音色已就绪」。
- 不把未知授权、未知备份、未接入登录态显示为成功。
- 任何禁用动作都说明原因，并尽可能给出下一步，例如「此文件为音乐；请先分离人声后再提取」。

### 7.3 音色的能力状态

| 状态 | 对用户的含义 | 下一步 |
| --- | --- | --- |
| `recording_needed` | 录音创建尚无足够样本 | 继续录制指定短句 |
| `quality_review` | 当前来源样本正在检查 | 等待或替换问题片段 |
| `speech_ready` | 该音色可生成语音 | 选择文案和表达风格 |
| `singing_samples_needed` | 该音色可做语音，但歌唱样本不足 | 按提示补录或导入演唱样本 |
| `singing_ready` | 该音色可用于歌曲演唱 | 进入歌曲工作台 |
| `archived` | 音色已归档 | 不再允许新生成 |

## 8. 实施前后的验收标准

后续实现必须满足：

1. 一段 TTS 成品可以从资产详情跳到它使用的音色。
2. 一段合格、已确认授权的单人音频可以不经下载/上传，直接创建音色。
3. 从音色详情能看到来源音频和所有引用它的作品。
4. 音乐、多人或授权未知音频不会静默出现在音色库。
5. 音乐、TTS、对话、导入音频都能进入“全部音频”；不能再只扫描输出目录顶层。
6. 归档/删除操作不会造成悬空音色或丢失历史作品的来源说明。
7. 存在旧 `personas.json` 时，旧音色仍可用，迁移状态对用户可见。
8. 用户可以在平台内直接录音；原始录音、处理后的参考片段与 `source_type=recorded` 均可追溯。
9. 音色只能由导入、录音或 AI 设计三种入口创建；每个音色可创建多个表达风格，所有新作品均可反查音色和表达风格。
10. “生成音乐”和“以选中音色演唱”在功能、状态与资产血缘上明确区分；模型不支持时不得展示后者为可用能力。
11. 归档音色后，平台阻止新的生成，并保留既有作品的音色快照。

## 9. 需要在写代码前拍板的决定

1. **素材使用提示**：本地模式采用一次性提示，还是每次导入都提示用户确认拥有使用许可？
2. **候选识别**：首版用用户手动标记“单人语音”，还是接入人声/说话人检测？
3. **资产存储**：首版以本地 SQLite/JSON 台账承载关系，还是直接引入数据库？
4. **迁移范围**：已有 `out/`、`out/music/`、`assets/reference_audio/` 与 `personas.json` 如何一次性建立初始台账？
5. **AI 设计入库**：AI 设计的试音是生成后自动注册，还是必须由用户确认“注册为音色”？
6. **录音方式**：首版支持浏览器直接录音、上传文件，还是两者同时支持？
7. **歌唱能力**：采用哪一种实际支持选中音色演唱的模型/服务；样本量、费用、分轨能力与失败边界是什么？

在以上决定明确前，不应开始改库、改接口或补 UI 按钮。
